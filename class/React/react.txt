React Interview Questions and Detailed Answers on useState

1. What is useState?
Answer:
useState is a React Hook used to add state to a functional component. It allows a component to remember and update data across re-renders.

In class components, state is written with this.state and this.setState().
In functional components, we use useState().

Example:
```jsx
import React, { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h2>Count: {count}</h2>
      <button onClick={() => setCount(count + 1)}>Increase</button>
    </div>
  );
}
```

Explanation:
- count is the current value of state
- setCount is the function used to update state
- useState(0) means initial value is 0
- when setCount is called, React re-renders the component and the updated count is shown on screen

2. What is the syntax of useState?
Answer:
```jsx
const [state, setState] = useState(initialValue);
```

Example:
```jsx
const [name, setName] = useState('Aman');
const [age, setAge] = useState(20);
const [isLoggedIn, setIsLoggedIn] = useState(false);
```

Explanation:
- first item = current state value
- second item = function to change the value
- initialValue can be number, string, boolean, object, array, etc.

3. Why do we use useState?
Answer:
Because React components re-render when state changes. useState helps us store values that must change dynamically based on user interaction or data updates.

Example:
```jsx
function ToggleButton() {
  const [isOpen, setIsOpen] = useState(false);

  return (
    <button onClick={() => setIsOpen(!isOpen)}>
      {isOpen ? 'Open' : 'Close'}
    </button>
  );
}
```

Explanation:
- isOpen stores a boolean
- clicking button flips the value
- the UI updates automatically

4. What is the difference between state and props?
Answer:
Props are values passed from parent to child.
State is local data inside a component that can change over time.

Example:
```jsx
function Parent() {
  const [name, setName] = useState('Aman');

  return <Child userName={name} />;
}

function Child({ userName }) {
  return <h2>Hello {userName}</h2>;
}
```

Explanation:
- Parent owns the state
- Parent passes that value to Child through props
- Child cannot modify the original state directly

5. Why do we use the setter function?
Answer:
Because direct mutation does not trigger a React re-render.
React only updates the UI when the state setter is called.

Wrong:
```jsx
let count = 0;
count = count + 1; // This does not re-render UI
```

Correct:
```jsx
const [count, setCount] = useState(0);
setCount(count + 1);
```

Explanation:
- React tracks state updates
- when you call setCount, React knows the component needs to re-render

6. What happens when state changes?
Answer:
When state changes, React re-renders the component and updates the UI.

Example:
```jsx
function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>{count}</p>
      <button onClick={() => setCount(count + 1)}>Add</button>
    </div>
  );
}
```

Explanation:
- first render: count = 0
- button click calls setCount(1)
- React re-renders with count = 1
- new value is displayed

7. Can we use multiple useState hooks in one component?
Answer:
Yes. We can manage multiple states in a single component.

Example:
```jsx
function UserInfo() {
  const [name, setName] = useState('Aman');
  const [age, setAge] = useState(20);

  return (
    <div>
      <p>Name: {name}</p>
      <p>Age: {age}</p>
      <button onClick={() => setAge(age + 1)}>Increase Age</button>
    </div>
  );
}
```

Explanation:
- each state is independent
- we can update one without affecting the other

8. How do you update state based on previous state?
Answer:
Use the updater function form.

Example:
```jsx
function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h2>Count: {count}</h2>
      <button onClick={() => setCount(prev => prev + 1)}>Increment</button>
    </div>
  );
}
```

Explanation:
- prev is the latest value of count
- this is safer when multiple updates happen quickly

Without prev:
```jsx
setCount(count + 1);
setCount(count + 1);
```

This may not always work correctly because both calls may use the old value.

Correct way:
```jsx
setCount(prev => prev + 1);
setCount(prev => prev + 1);
```

9. What is stale state?
Answer:
Stale state happens when a state value is outdated because the component is using an older render value.

Example:
```jsx
function Counter() {
  const [count, setCount] = useState(0);

  const handleDoubleClick = () => {
    setCount(count + 1);
    setCount(count + 1);
  };

  return (
    <div>
      <h2>{count}</h2>
      <button onClick={handleDoubleClick}>Increase Two Times</button>
    </div>
  );
}
```

Problem:
- both updates use the same old count value
- result may be 1 instead of 2

Fix:
```jsx
setCount(prev => prev + 1);
setCount(prev => prev + 1);
```

This ensures each update uses the latest value.

10. Why should we not mutate state directly?
Answer:
React state should be treated as immutable. If we mutate the original object or array, React may not detect the change.

Wrong:
```jsx
const [user, setUser] = useState({ name: 'Aman', age: 20 });

user.age = 25; // bad
setUser(user);
```

Correct:
```jsx
setUser({ ...user, age: 25 });
```

Explanation:
- ...user creates a new object
- React sees a new reference and re-renders

11. How do you update an object in state?
Answer:
Use spread operator to create a new object.

Example:
```jsx
function UserProfile() {
  const [user, setUser] = useState({ name: 'Aman', age: 20 });

  const updateAge = () => {
    setUser({ ...user, age: 21 });
  };

  return (
    <div>
      <p>{user.name} is {user.age} years old</p>
      <button onClick={updateAge}>Update Age</button>
    </div>
  );
}
```

Explanation:
- we keep the old object values
- change only the needed property
- create a new object so React can detect the update

12. How do you update an array in state?
Answer:
Use a new array instead of modifying the original.

Example:
```jsx
function TodoList() {
  const [items, setItems] = useState(['Apple', 'Banana']);

  const addItem = () => {
    setItems([...items, 'Orange']);
  };

  return (
    <div>
      <ul>
        {items.map((item, index) => <li key={index}>{item}</li>)}
      </ul>
      <button onClick={addItem}>Add Fruit</button>
    </div>
  );
}
```

Explanation:
- [...items, 'Orange'] creates a new array
- old values remain intact
- React re-renders with new item included

13. What is lazy initialization in useState?
Answer:
If initial state requires computation, we can pass a function to useState. This function runs only once during the initial render.

Example:
```jsx
function ExpensiveCounter() {
  const [value, setValue] = useState(() => {
    console.log('Running once');
    return 10;
  });

  return <h2>{value}</h2>;
}
```

Explanation:
- the function inside useState runs only on first render
- used when computing initial state is expensive

14. Can useState store arrays and objects?
Answer:
Yes. useState can hold any JavaScript value.

Example:
```jsx
const [student, setStudent] = useState({ name: 'Aman', marks: 90 });
const [friends, setFriends] = useState(['Rohit', 'Karan']);
const [online, setOnline] = useState(true);
```

15. What is a controlled component using useState?
Answer:
In a controlled input, the value of the input is stored in state.

Example:
```jsx
function InputExample() {
  const [name, setName] = useState('');

  return (
    <div>
      <input
        type="text"
        value={name}
        onChange={(e) => setName(e.target.value)}
      />
      <p>Hello {name}</p>
    </div>
  );
}
```

Explanation:
- input value is controlled by React state
- every key press updates state
- UI always reflects latest input value

16. How do you create a toggle button using useState?
Example:
```jsx
function Toggle() {
  const [isOn, setIsOn] = useState(false);

  return (
    <button onClick={() => setIsOn(!isOn)}>
      {isOn ? 'ON' : 'OFF'}
    </button>
  );
}
```

Explanation:
- isOn is boolean
- !isOn flips its value every click

17. How do you handle forms with useState?
Answer:
Store form values in state and update them on input change.

Example:
```jsx
function LoginForm() {
  const [form, setForm] = useState({ email: '', password: '' });

  const handleChange = (e) => {
    const { name, value } = e.target;
    setForm({ ...form, [name]: value });
  };

  return (
    <form>
      <input
        type="email"
        name="email"
        value={form.email}
        onChange={handleChange}
      />
      <input
        type="password"
        name="password"
        value={form.password}
        onChange={handleChange}
      />
    </form>
  );
}
```

Explanation:
- each field is controlled by state
- we update form object without replacing other fields

18. Can we use useState with arrays of objects?
Yes. Example:
```jsx
function UserList() {
  const [users, setUsers] = useState([
    { id: 1, name: 'Aman' },
    { id: 2, name: 'Karan' }
  ]);

  const addUser = () => {
    setUsers([...users, { id: 3, name: 'Rahul' }]);
  };

  return (
    <div>
      {users.map(user => <p key={user.id}>{user.name}</p>)}
      <button onClick={addUser}>Add User</button>
    </div>
  );
}
```

19. Why is state asynchronous?
Answer:
React may batch multiple state updates together for performance. This means the new state is not always immediately available after calling the setter.

Example:
```jsx
const [count, setCount] = useState(0);

const handleClick = () => {
  setCount(count + 1);
  setCount(count + 1);
};
```

In such cases, using previous state is safer.

20. What is the best short interview answer for useState?
Answer:
useState is a React Hook used to store and update local component state in functional components. It returns the current value and a setter function. When the setter is called, React re-renders the component and updates the UI. It is commonly used for counters, forms, toggles, lists, and user interaction-based UI.

Example:
```jsx
const [count, setCount] = useState(0);
```

This means:
- count holds the current value
- setCount updates the value
- React re-renders the component after the update

22. Best practice summary
- Always use the setter function to update state
- Never mutate state directly
- Use previous state when updates depend on current value
- Use state for values that change in UI
- Use props to pass data from parent to child
- Use multiple useState hooks when required

23. Final practical example
```jsx
import React, { useState } from 'react';

function App() {
  const [count, setCount] = useState(0);
  const [name, setName] = useState('Aman');

  return (
    <div>
      <h1>Count: {count}</h1>
      <button onClick={() => setCount(prev => prev + 1)}>Increment</button>

      <input
        value={name}
        onChange={(e) => setName(e.target.value)}
      />

      <p>Hello {name}</p>
    </div>
  );
}
```

Explanation:
- count is updated with previous value to avoid stale state
- name is updated from input value
- both are managed using React state

This is the core idea behind useState in React.

Remember:
State is the memory of the component.
When the state changes, React updates the UI.

Additional useState Interview Questions (Easy to Hard)

24. What is the difference between useState and useEffect?
Answer:
useState stores data.
useEffect runs code after render, usually for side effects like API calls, timers, subscriptions, or DOM updates.

Example:
```jsx
const [count, setCount] = useState(0);

useEffect(() => {
  console.log('Component rendered');
}, [count]);
```

25. Can useState accept a function as an initial value?
Answer:
Yes. This is called lazy initialization.

Example:
```jsx
const [items, setItems] = useState(() => ['A', 'B', 'C']);
```

It is useful when the initial value is expensive to compute.

26. Why is useState called a Hook?
Answer:
A Hook is a special function that lets functional components use React features like state and effects.

27. Can we call useState conditionally?
Answer:
No. Hooks must be called at the top level of the component, not inside loops, conditions, or nested functions.

28. What happens if we call useState inside a loop?
Answer:
React will not correctly preserve state order, which can cause bugs. Hooks must be called in the same order every render.

29. What is a primitive value in state?
Answer:
Numbers, strings, booleans, null, and undefined are primitive values.

Example:
```jsx
const [name, setName] = useState('Aman');
const [isActive, setIsActive] = useState(true);
const [count, setCount] = useState(0);
```

30. What is a non-primitive value in state?
Answer:
Objects and arrays are non-primitive values.

Example:
```jsx
const [user, setUser] = useState({ name: 'Aman' });
const [list, setList] = useState([1, 2, 3]);
```

31. Why is React state considered immutable?
Answer:
Because we should never directly modify the current state. Instead, create a new value and update it.

32. How do you handle a checkbox using useState?
Example:
```jsx
const [checked, setChecked] = useState(false);

<input type="checkbox" checked={checked} onChange={() => setChecked(!checked)} />
```

33. How do you reset state to its initial value?
Example:
```jsx
const initialState = { name: '', email: '' };
const [form, setForm] = useState(initialState);

const resetForm = () => setForm(initialState);
```

34. How do you update nested object values?
Example:
```jsx
const [profile, setProfile] = useState({ name: 'Aman', address: { city: 'Delhi' } });

setProfile({
  ...profile,
  address: { ...profile.address, city: 'Mumbai' }
});
```

35. Can we use useState to store a function in state?
Answer:
Yes, but usually not recommended unless you truly need to store a function. For event handlers, use callback functions directly.

36. What is the difference between using a regular variable and useState?
Answer:
A normal variable does not trigger re-render.
A state variable does.

Example:
```jsx
let count = 0;
```

This value changes, but React will not display it automatically.

37. Why do we use `setState(prev => prev + 1)` in many cases?
Answer:
Because it guarantees the update uses the latest state value, especially when many updates happen before re-render.

38. What is a common bug with `setCount(count + 1)`?
Answer:
If you call it many times in one event, it may use stale values.

Example:
```jsx
const handleClick = () => {
  setCount(count + 1);
  setCount(count + 1);
};
```

This may not produce the expected total.

39. What is the correct pattern for multiple updates?
Answer:
Use the previous state function.

```jsx
const handleClick = () => {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
};
```

40. What is the difference between state initialization value and setter update?
Answer:
The initial state is used only on the first render.
Setter updates happen on later renders.

41. Can useState be used with data fetched from API?
Answer:
Yes. Very common.

Example:
```jsx
const [users, setUsers] = useState([]);

useEffect(() => {
  fetch('/api/users')
    .then(res => res.json())
    .then(data => setUsers(data));
}, []);
```

42. Why do we often use useState for modal open/close logic?
Answer:
Because the modal is a UI state: open or closed.

Example:
```jsx
const [open, setOpen] = useState(false);
```

43. What is a good pattern for form validation with useState?
Answer:
Store values and error state separately.

Example:
```jsx
const [email, setEmail] = useState('');
const [error, setError] = useState('');
```

44. How do you update only a part of an object in state?
Answer:
Use spread operator and update only the target field.

Example:
```jsx
const [student, setStudent] = useState({ name: 'Aman', score: 80 });

setStudent({ ...student, score: 90 });
```

45. What is the difference between immutable and mutable updates?
Answer:
Mutable update changes the original object in place.
Immutable update creates a new copy and leaves the old value unchanged.

46. Why is immutable update important in React?
Answer:
It allows React to detect changes and decide whether to re-render properly.

47. Why are arrays often updated with map/filter?
Answer:
Because these methods return new arrays without mutating the original.

Example:
```jsx
setItems(items.filter(item => item !== 'Banana'));
```

48. How do you remove an item from a list with useState?
Example:
```jsx
const [items, setItems] = useState(['A', 'B', 'C']);

const removeItem = (value) => {
  setItems(items.filter(item => item !== value));
};
```

49. How do you add an item to a list with useState?
Example:
```jsx
const [items, setItems] = useState(['A']);

const addItem = () => {
  setItems([...items, 'B']);
};
```

50. How do you update the selected item in a list?
Example:
```jsx
const [selected, setSelected] = useState(null);

<button onClick={() => setSelected(item.id)}>Select</button>
```

51. What is the role of `key` when rendering a list with state?
Answer:
`key` helps React identify items in a list and maintain stable rendering.

52. What is controlled input validation with useState?
Answer:
We store the input value in state and validate it during input or submit.

53. How do you implement a password show/hide toggle?
Example:
```jsx
const [showPassword, setShowPassword] = useState(false);

<input type={showPassword ? 'text' : 'password'} />
<button onClick={() => setShowPassword(!showPassword)}>Show</button>
```

54. What is a loading state in useState?
Example:
```jsx
const [loading, setLoading] = useState(false);
```

55. What is a success/error state?
Example:
```jsx
const [success, setSuccess] = useState(false);
const [error, setError] = useState('');
```

56. How do you implement pagination state?
Example:
```jsx
const [page, setPage] = useState(1);
```

57. What is a common use of useState in authentication flow?
Answer:
Storing login status and user details.

Example:
```jsx
const [isLoggedIn, setIsLoggedIn] = useState(false);
const [user, setUser] = useState(null);
```

58. Why are forms a common use case for useState?
Answer:
Because form values change as user types and need to be tracked in real time.

59. Why do interviewers ask about stale state?
Answer:
Because it tests whether the candidate understands React batching and async state updates.

60. What is a strong final answer for useState in an interview?
Answer:
`useState` is a React Hook used to manage data that changes over time in a functional component. It returns a state value and a setter function, and when the setter is called, React re-renders the component so the new UI is shown. It is useful for counters, forms, toggles, lists, modal visibility, and login status. The most important best practice is to never mutate state directly and to use the previous state callback when updates depend on the current state.

Example:
```jsx
const [count, setCount] = useState(0);

const increase = () => setCount(prev => prev + 1);
```

This is the core idea behind state management in React.
